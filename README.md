# GROUP9 TUP Learning & Assessment System

GROUP9 is now a plain JavaScript React/Vite SPA backed by an Express REST API.

## Run locally

1. Copy `server/.env.example` to `server/.env` and set a real MongoDB Atlas connection string and JWT secret. Do not leave the example `your-cluster.mongodb.net` hostname in place.
2. Optionally copy `client/.env.example` to `client/.env`.
3. Install dependencies from the repository root:

```powershell
npm install
```

4. Start both applications:

```powershell
npm run dev
```

The Vite client runs at `http://localhost:5173` and the Express API runs at `http://localhost:5000`.

## Production

```powershell
npm run build
npm start
```

Deploy the `client/dist` folder to Vercel or Netlify and deploy `server` to Render, Railway, or a Vercel Express wrapper. Set `VITE_API_URL` and `CLIENT_URL` to the deployed origins.

## Structure

- `client/src`: React pages, reusable components, auth context, router, and export utilities.
- `server`: Express entry point, JWT middleware, Mongoose models, REST endpoints, and upload handling.

## Topic materials

Place lesson assets in `public/topics/`. The API recursively indexes that directory through
`GET /api/topic-assets?topicNum=<number>` and serves files from `/topic-assets/`.
Existing files named `ITPE3-G2`, `ITPE3-G3`, `ITPE3-G5`, and `ITPE3-G6` are automatically
associated with Topics 2, 3, 5, and 6. PDFs render in the lesson viewer; PPTX files are
available as browser downloads because native browser rendering of PowerPoint files is not
supported without an external viewer.

Faculty can manage each topic from the subject roadmap using the topic editor route:
`/subjects/:subjectId/topic/:topicNumber/edit`. The editor supports rich-text notes,
PDF/PPT/PPTX uploads, custom in-app slides, summaries, and the verified-complete badge.
Students use `/subjects/:subjectId/topic/:topicNumber/view`; this view enforces the
previous-topic passing requirement and renders the published notes, presentation, custom
slides, summary, and verification status.

Student IDs are generated by the server during registration (and backfilled when an
existing student signs in) in the format `TUP-STU-YYYY-XXXXXX`. Student IDs cannot be
edited from the profile page. Registration and `/profile` support an optional profile
image upload.
